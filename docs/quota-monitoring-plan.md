# 额度监测方案

## 目标

在 QDII 数据看板中增加「额度监测」Tab，按 **基金 + 份额 + 渠道** 展示纳斯达克 100 QDII 基金的申购额度，重点区分：

- 直销渠道额度
- 第三方/代销渠道额度
- 公告未区分渠道时的全渠道额度

额度数据以中国证监会基金电子披露网站（CSRC）的基金公告为主，基金公司官网作为来源入口和人工核对依据。公告是事件驱动的，页面必须同时显示“最后公告日期”和“最后检查时间”，不能把“今天检查过”误解为“今天有新公告”。

## 数据模型

- `quota_company`：基金公司及官网入口。
- `quota_fund`：基金公司、基金代码、份额、币种；`csrc_code` 用于 I 类等子份额映射母基金公告代码。
- `quota_source`：CSRC/公司官网来源、最后检查时间、最后成功时间、错误信息。
- `quota_announcement`：公告标题、发布日期、原文链接、PDF 文本、解析状态、是否已读。
- `quota_limit`：按渠道拆分的额度记录，字段包括：
  - `channel_type`：`direct` / `agency` / `all`
  - `channel_name`：直销电子平台、直销柜台、代销机构等
  - `status`：`amount_cap` / `paused` / `normal` / `unknown`
  - `amount`、`currency`、`limit_text`
  - `business_type`：申购、定投、转换
  - `effective_from`
  - `confidence`、`is_manual`
- `quota_run`：每次监测任务的开始/结束时间、结果和错误。

## 解析规则

1. 只处理标题包含申购、限额、限制、暂停、恢复、大额、上限、金额等关键词的公告。
2. 排除季报、年报、招募说明书、净值、分红、停牌、估值、节假日等非额度公告。
3. 从标题和 PDF 正文中识别渠道：
   - “直销电子交易平台”“直销机构”“直销柜台” → 直销
   - “代销机构”“代销渠道”“第三方销售” → 第三方/代销
   - 没有渠道词 → 全渠道/未区分
4. 金额优先匹配“不超过人民币 X 元”“限制金额 X 元”“限额 X 元”“上限 X 元”等表达。
5. 同一公告同时出现直销和代销时，拆成多条 `quota_limit`，关联同一公告。
6. 保留公告原文链接、原文片段、解析置信度；低置信度允许人工修正。
7. 人工修正记录 `is_manual=1`，后续公告不会静默覆盖人工结果。

## 页面

- Tab 名称：**额度监测**
- 顶部：基金公司数、基金数、直销受限数、第三方受限数、最后检查时间、立即检查按钮。
- 主表：基金/公司、直销额度、第三方额度、全渠道额度、最后公告、来源、操作。
- 筛选：基金搜索、基金公司、只看今日变化、只看受限。
- 详情：按渠道展示当前额度、公告历史、来源链接、人工修正表单。
- 原有“日额度变动记录”保留在页面下方，作为全渠道高频参考，不与公告渠道额度混为一谈。

## 实施阶段

- Phase 1：表结构、10 家公司种子数据、额度监测 Tab、人工修正。
- Phase 2：CSRC 公告增量采集与 PDF 解析（本阶段完成）。
- Phase 3：基金公司官网定向适配，补充公告时效和更细的渠道说明。
- Phase 4：渠道维度提醒、历史曲线、更多基金公司和份额。

## 限制

- 公告通常只披露到“直销/代销”层级，未必逐个第三方平台披露；页面不伪造平台额度。
- 基金公司 App/小程序可能有登录和反爬限制，不做自动登录抓取。
- 公告发布和额度实际生效之间可能存在时差，页面以公告生效日为准。
- 解析结果必须保留原文链接；重要操作前仍需以基金公司最新公告和 App 为准。
