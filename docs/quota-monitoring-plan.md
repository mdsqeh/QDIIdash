# 额度监测方案

## 目标

在 QDII 数据看板中增加「额度监测」Tab，自动发现纳斯达克 100 QDII 基金，按 **基金 + 份额 + 渠道** 展示申购额度，重点区分：

- 直销渠道额度
- 第三方/代销渠道额度
- 公告未区分渠道时的全渠道额度

额度数据以中国证监会基金电子披露网站（CSRC）的基金公告为主，基金公司官网作为来源入口和人工核对依据。公告是事件驱动的，页面必须同时显示“最后公告日期”和“最后检查时间”，不能把“今天检查过”误解为“今天有新公告”。

## 清单来源：复用主页纳斯达克 100 筛选

不再维护静态基金清单。额度监测直接复用主页已有的纳斯达克 100 筛选口径：

```text
基金名称 + 基金类型 同时包含（纳斯达克 | nasdaq）和 100
```

对应主页 `templates/index.html` 的 `matchesPresetFilter(row, 'nasdaq100')`。

数据直接读取主页的 `funds` 表，不额外维护一套基金代码列表。主页 QDII 数据每天 21:00 更新，额度监测在每次公告检查前同步一次清单。`quota/schema.py` 里的静态种子只用于首次启动、主页数据尚未采集时的兜底；正常运行以动态清单为准。

### 纳入和排除

纳入：

- 场外申购的纳斯达克 100 QDII 指数基金
- ETF 联接基金
- 场外 LOF
- 同一只基金的全部份额类别和币种

排除：

- `market='场内'` 的纯场内 ETF。场内 ETF 没有“日申购额度”概念，不纳入额度监测。
- 非纳斯达克 100 产品
- 非 QDII 产品

### 新基金和新公司发现

发现机制不依赖手工维护代码列表：

1. 主页 QDII 数据每天更新 `funds` 表，新增基金最晚在下一次主页采集后进入候选池。
2. 额度监测在每次公告检查前、以及应用启动时调用 `sync_nasdaq100_funds`。
3. 同步时重新执行主页纳斯达克 100 筛选，并仅保留 `market='场外'`。
4. 从基金名称中“纳斯达克/Nasdaq”之前的前缀识别基金公司简称。
5. 已存在的公司直接复用；新公司自动创建 `quota_company` 记录，默认启用。
6. 新基金代码自动插入 `quota_fund`，并归组到同一基础基金，复用母基金 CSRC 代码。
7. 新基金首次检查抓到的历史公告标记为已读，避免历史公告刷屏；之后的新公告正常进入未读提醒。
8. 新公司自动创建时只有简称，`full_name` 暂用简称、官网为空；不影响按基金代码查询 CSRC 公告，后续可人工补充公司元数据。

## 清单同步规则

### 同步时机

- 每次公告检查前同步一次
- 页面提供“立即检查”，同时完成清单同步和公告检查
- 主页 QDII 数据更新后，下一次公告检查自动发现新增基金或新增份额

### 新增和更新

对主页清单中的每只基金：

1. 从名称中“纳斯达克/Nasdaq”之前的前缀识别基金公司简称，按简称精确匹配；匹配不到时自动创建公司
2. 解析份额类别：A/C/I/D/E，无法识别时默认 A
3. 解析币种：名称含“美元”则为 USD，否则为 CNY
4. 按“基金公司 + 去掉份额/币种后的基础名称”归组
5. 同组选择一个可用的 CSRC 母基金代码，写入 `csrc_code`
6. 新代码插入 `quota_fund`
7. 已存在代码更新名称、份额、币种、来源和最后出现时间
8. 不删除历史公告、额度记录和人工修正

例如：

- `016452` 南方纳斯达克100 A
- `016453` 南方纳斯达克100 C
- `021000` 南方纳斯达克100 I

三只份额归为同一组，`021000` 用同组的 `016452` 查询 CSRC 公告，再按 I 类过滤。

### 失效处理

- 只有成功读取到完整主页基金表时才做失效判断
- 未出现在完整清单中的基金标记 `enabled=0`
- 历史公告、额度记录、人工修正全部保留
- 主页数据为空或明显不完整时，不自动停用基金

## 数据模型

- `quota_company`：基金公司及官网入口；新公司可由发现机制自动创建。
- `quota_fund`：基金公司、基金代码、份额、币种、`csrc_code`、`discovery_source`、`last_seen_at`、启用状态。
- `quota_source`：CSRC/公司官网来源、最后检查时间、最后成功时间、错误信息。
- `quota_announcement`：公告标题、发布日期、原文链接、PDF 文本、解析状态、是否已读。
- `quota_limit`：按渠道拆分的额度记录，字段包括：
  - `channel_type`：`direct` / `agency` / `all`
  - `channel_name`：直销电子平台、直销柜台、代销机构等
  - `status`：`amount_cap` / `paused` / `normal` / `unknown`
  - `amount`、`currency`、`limit_text`
  - `business_type`：申购、定投、转换
  - `effective_from`
  - `confidence`、`is_manual`
- `quota_run`：每次监测任务的开始/结束时间、结果和错误。

## 公告检查规则

对清单中每只启用的基金：

1. 用 `csrc_code` 查 CSRC 基金 ID
2. 拉取该基金公告列表
3. 用公告 `external_id` 判断是否已抓取
4. 只下载和解析新公告
5. 保存原文链接、PDF 文本、解析结果
6. 更新最后公告日期和最后检查时间
7. 新公告进入未读提醒；新发现基金首次回填的历史公告标记为已读，避免历史公告刷屏
8. 同一母基金的多份额共享 CSRC 公告页和 PDF 文本缓存，避免按份额重复下载；每个份额仍独立解析、入库和标记已读

定时检查时间：

- 每日 8:10
- 每日 12:10
- 每日 17:10
- 页面可手动触发

## 解析规则

1. 只处理标题包含申购、限额、限制、暂停、恢复、大额、上限、金额等关键词的公告。
2. 排除季报、年报、招募说明书、净值、分红、停牌、估值、节假日等非额度公告；因境外休市/非交易日的一次性暂停提示也不计入额度，但保留“继续暂停申购”等持续状态公告。
3. 排除不改变申购额度的公告，例如“最低申购金额/最低赎回/最低持有份额”和“新增申购赎回代理机构/代办券商”；这些公告可能同时出现“申购”“金额”等词，但不能当成额度调整。
4. 按份额过滤：
   - A 类公告应用到 A 类份额
   - C 类公告应用到 C 类份额
   - I 类公告应用到 I 类份额
   - 同时写多个份额的公告，应用到对应份额
   - 未写份额类别的公告，应用到同组所有份额
   - 正文份额表明确标记“否”的份额不应用该公告；只有标记“是”的份额应用
   - 正文出现多份额代码表时，以代码表为准；表中没有该份额代码的，不套用其他份额的金额，标记为待确认
   - 单个“基金代码：XXXXXX”只是基金主代码，不视为多份额代码表
5. 从标题和 PDF 正文中识别渠道：
   - “直销电子交易平台”“直销机构”“直销柜台” → 直销
   - “代销机构”“代销渠道”“第三方销售” → 第三方/代销
   - 没有渠道词 → 全渠道/未区分
   - 份额表路径优先使用标题中明确写出的渠道，避免正文说明文字把直销公告扩展成代销额度
6. 金额优先匹配“不超过人民币 X 元”“限制金额 X 元”“限额 X 元”“上限 X 元”“调整为 X 元”等表达；金额必须带“元/万元/美元/万美元”单位，避免把“总规模 X 亿元”误当成单日申购额度。
7. 份额表按代码行和“限制申购金额”数值行逐份额解析；数值行必须与代码数量一致，支持“1 万美元”“10 元”等带单位写法，并识别“-”/0 为不限额。
8. 标题为“暂停申购”（不含“大额”）时，整只基金/对应份额按暂停处理，正文里出现的旧金额不覆盖暂停状态；“暂停大额申购”但没有解析到金额时标记为待确认，而不是直接当成全额暂停。
9. 同一公告同时出现直销和代销时，拆成多条 `quota_limit`，关联同一公告。
10. 保留公告原文链接、原文片段、解析置信度；低置信度允许人工修正。
11. 人工修正记录 `is_manual=1`，后续公告不会静默覆盖人工结果。

## 页面

- Tab 名称：**额度监测**
- 顶部：基金公司数、基金数、直销受限数、第三方受限数、最后检查时间、立即检查按钮。
- 主表：基金/公司、份额/币种、直销额度、第三方额度、全渠道额度、最后公告、来源、操作。
- 筛选：基金搜索、基金公司、只看今日变化、只看受限；全渠道额度同时参与“有限额 / 有暂停 / 可申购”筛选，但直销、第三方分渠道统计只统计各自渠道，避免重复计数。
- 详情：按渠道展示当前额度、公告历史、来源链接、人工修正表单。
- 原有“日额度变动记录”保留在页面下方，作为全渠道高频参考，不与公告渠道额度混为一谈。

## 实施阶段

- Phase 1：动态清单同步，复用主页纳斯达克 100 筛选，覆盖全部 17 家公司、59 只场外份额，并支持新公司自动发现（已完成）。
- Phase 2：CSRC 公告增量采集与 PDF 解析（已完成）。
- Phase 3：基金公司官网定向适配，补充公告时效和更细的渠道说明。
- Phase 4：渠道维度提醒、历史曲线、扩展到更多指数和全市场。

## 限制

- 动态清单能解决漏基金、漏份额和新增基金不自动出现的问题。
- 自动创建的新公司只有简称，官网和公司全称需要后续补充；这不影响 CSRC 按基金代码查询。
- 动态清单不能解决“公告只写全渠道、但直销和代销实际额度不同”的问题。
- 动态清单不能替代基金公司 App/直销平台里的实时额度；未发公告的变化仍需人工修正。
- 公告通常只披露到“直销/代销”层级，未必逐个第三方平台披露；页面不伪造平台额度。
- 基金公司 App/小程序可能有登录和反爬限制，不做自动登录抓取。
- 公告发布和额度实际生效之间可能存在时差，页面以公告生效日为准。
- 美元份额先纳入清单和公告监测；金额解析如遇美元表述，低置信度时以人工修正为准。
- 解析结果必须保留原文链接；重要操作前仍需以基金公司最新公告和 App 为准。
